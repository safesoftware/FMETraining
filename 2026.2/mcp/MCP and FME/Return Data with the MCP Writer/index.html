MCP Tool Response

For each MCP tool call to an FME Flow MCP server, FME Flow returns the job status, whether the workspace succeeds or fails, back to the MCP client. This is useful for MCP tools that trigger an action such as writing data to a database, updating a file, or sending a notification, since the client only needs to know whether the operation completes. However, many MCP workflows need to return data to the requesting client to fully leverage MCP and FME workflows. The MCP writer communicates information from the FME workspace running as an MCP tool back to the MCP client that made the request. 

MCP Writer

The MCP writer allows you to send a structured MCP tool response from an FME workspace that an MCP client can consume directly. The MCP writer accumulates all features routed to it in the workspace into a JSON-RPC 2.0-formatted response document, which FME Flow routes to the calling MCP client. The output response conforms to the tool response format and requirements defined in the MCP Tools Specification. From the MCP user's or client's perspective, calling an MCP tool and receiving a detailed response appears seamless, as the response is formatted in JSON in the background. 

The MCP writer currently supports returning text, image, and audio content as JSON for MCP tools. Each content type is represented as a separate feature type in the workspace, and you can include one or more content types in the same workspace depending on what the tool needs to return.

Text is the most common output type and is supported by every MCP client. Text content is passed to the writer as a plain string attribute, typically the result of a calculation, a formatted summary, a list of records, or any other text produced by the workspace. For data-heavy tools like counting features in an area or summarizing building plans, text is typically the right choice, and you simply build what you want to send as the MCP response using an AttributeCreator and route it to the writer feature type. For more complex responses, you can format details into a JSON object to pass back to the MCP client. 

Image content allows a tool to return visual output, such as a generated map, chart, or spatial visualization, directly in the response. Image content is passed to the writer as Base64-encoded data along with a MIME type. To retrieve an image to return as an MCP response, use an AttributeFileReader to read the image file as Base64, then an AttributeCreator to add a mimeType attribute (for example, image/png). FME handles the encoding; the client receives the image directly in the response. Note that some MCP clients have file size limits, so large images may need to be resampled or compressed before being written.

Audio content works similarly to image — passed as Base64-encoded data with a MIME type (for example, audio/mpeg). This content type supports use cases where the tool output is an audio file or clip. Support for audio content varies by MCP client, so you should test the audio playback with your target MCP client, likely an AI model, before building a tool that uses audio output.

When you create an MCP tool on FME Flow using a workspace containing an MCP writer, FME Flow will display the MCP icon next to the workspace name. It signifies that the workspace has an MCP writer and will return additional information to the MCP client when the tool is called. 

Interpreting Tool Results

Once FME Flow returns the tool result to the MCP client, the AI model is responsible for interpreting it; however, different AI agents may interpret the same result in different ways. A response that one model renders as a formatted table, another might display as plain text. An image that one client shows inline, another might describe in words.

To help guide the AI toward a correct interpretation, the MCP writer supports optional annotation values, audience, and priority for each content type. The audience and priority values give the MCP client hints on how to handle the MCP response, such as how to display the content and its purpose. Again, whether an AI MCP client honors these values depends on the client itself, and you should test your intended AI client to understand and predict how it behaves. 

And again, your tool description also helps the MCP client understand what to expect from the tool's output, its purpose, and how to best display the information back to the user. A tool description that specifies the format and structure of the output gives an AI model the context it needs to handle the response correctly and present it usefully. A vague description leaves the interpretation up to each AI model, which can produce inconsistent results across different clients, or even different sessions and requests with the same client.
