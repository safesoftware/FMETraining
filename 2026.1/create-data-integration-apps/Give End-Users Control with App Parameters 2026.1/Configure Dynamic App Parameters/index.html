Dynamic Parameters

So far, the user parameters you have used in the training are static, meaning the parameter settings, including choice options and default values, are set when you create the workspace and workspace app. FME Flow workspace apps also support dynamic parameters, where you can set user parameter settings and default values that differ and are set dynamically when the app loads or from an external source. Dynamic parameters add flexible app configurations and give users the most up-to-date parameter data when they access your app. By dynamically configuring the parameters from an external source, one app can serve multiple audiences, and parameter choices and defaults can be maintained by whoever owns the data rather than workspace authors. For the person using the app, this shows up as a shorter, more accurate form: a preset default is one less decision they have to make, and a choice list built from current data means they cannot pick an option that no longer returns anything. 

Dynamic parameters let a JSON schema dynamically change default values or available choice options for user parameters at runtime. The app author is responsible for linking the JSON schema to an app when creating the app, using the Dynamic Parameter Configuration section. The workspace app may load the JSON schema at launch from an external source, or directly from the URL the app launches with. 

URL-Based Configuration

This option uses the app URL to pass URL-encoded JSON parameter configurations when launching the app. The URL must supply the configuration for the allowed parameters through a query string parameter named dynamicParameterData.

URL-based configuration is most useful for bookmarking app configurations, chaining workspace apps together, or loading app defaults when launching the app from an external application. 

We will return to cover URL-based dynamic parameter configurations in the Set Parameters with Query Strings lesson. 

Configuration Loading at Launch

This option enables FME Flow workspace apps to pull dynamic parameter data from external sources when the app loads. As of FME 2026.1, workspace apps support loading the JSON schema for parameter configurations from: 

  • Resource: a JSON file stored in FME Flow Resources. 
  • Workspace: a workspace that returns the required JSON. 
  • URL: a web address that links to the JSON, such as an external web service or Data Virtualization endpoint. 

To configure these, the app author selects the data source and provides the URL, Resources file, or workspace that sources the JSON. When the app loads, it reads the JSON schema and populates the parameter options or default values accordingly. 

Loading app parameter configurations at app launch lets you link multiple FME workflows and control parameter options or values. For example, you may have an FME Flow automation that triggers in response to an external event and writes a dynamic parameter configuration based on the event to a JSON file in Resources. 

The workspace that pulls the dynamic parameter configuration is different from the workspace the app runs in, so you will use two workspaces to configure a workspace app that launches with dynamic parameters from a workspace. The next lesson, Populate App Parameters from a Workspace, will cover how to use a workspace to supply dynamic parameters to an app. 

To confirm whether your parameter configuration will work, you can test and preview the parameter source while building your workspace app. Test displays the parameter configuration the data source currently returns, and Preview shows the parameters as they would appear in the app. 

Dynamic Parameter JSON Configuration

The JSON array for dynamic parameter configuration contains one object per parameter you want to control. Each object names the parameter and then sets its default value, its choices, or both:

[
  {
    "name" : "date",
    "defaultValue" : "20260519"
  },
  {
    "name" : "event_type",
    "defaultValue" : "HAZARD",
    "choices" : [
      { "display" : "Hazard",      "value" : "HAZARD" },
      { "display" : "Ice Covered", "value" : "ICE_COVERED" }
    ]
  }
]

The name has to match the parameter's identifier in the workspace, or FME ignores the object and the configuration. The display is what the user sees and value is what the workspace receives, similar to creating options for the user parameter manually. Any parameter the JSON doesn't mention keeps whatever the workspace already set for the parameter.

Whether the source is a URL, Resource file, or workspace, the JSON schema must follow this structure to successfully populate the parameters dynamically. To help with the JSON schema, the dynamic parameters guide explains the schema and generates starting JSON arrays for each source type. 

 

Exercise

Jennifer, a GIS Specialist, has created a workspace app that maps traffic events and alerts in British Columbia using DriveBC's Open511 API. You may filter the events by date, event type, and region. Currently, the app uses choice options Jennifer set up when she created the workspace. However, Jennifer's list of choice options doesn't include all the values you can filter for using the API. Rather than editing the workspace each time the API's options change, she wants the choice list to come from a JSON file she or a colleague can edit and update.

In this exercise, you will:

  • Configure dynamic parameters for a workspace app.
  • Load that configuration from a JSON file in Resources.
  • Run the workspace app with and without dynamic parameter configurations.

1) Run Workspace App

Jennifer has already created the workspace app in FME Flow. It uses the data streaming service and displays the web map of filtered traffic events directly in the browser.

  • Navigate to FME Flow and open Flow Apps. 
  • Under the Workspace Apps tab, find the BCTrafficEvents app and click the icon in the View column to open the app. 

    • The app loads in another browser tab.
  • Interact with the parameters to see the event-filtering options. 
    • The Filter by Date parameter uses a calendar to select a date. The Filter by Event Type only lists four possible traffic events to filter by. The Filter by Region includes the Lower Mainland, Rocky Mountain, and Vancouver Island districts. 
    • The current options in the app don't fully capture the available event types and regions available through the Open511 API.

2) Inspect Configuration JSON File

The JSON file with new parameter configurations is already on FME Flow for the workspace app to reference. 

  • Close the app tab and return to the FME Flow tab.
  • Open Resources and browse to the Data folder.
  • Open the Configurations folder. 

  • Click the traffic_parameters.json file in that folder.

    • The JSON file lists a default date value, different choice options for the traffic event type, and additional districts in BC to filter events. 

3) Enable and Configure Dynamic App Parameters

  • Return to Flow Apps and the Workspace Apps tab. 
  • Click on the BCTrafficEvents app to edit it. 

  • Scroll down and expand Dynamic Parameter Configuration.
  • Toggle on the Enable Dynamic Parameters option. 

  • Under App Launch Settings, toggle on Enable Configuration Loading at Launch. 
  • Set the Data Source to Resource. 
  • For Resource, click Browse Resources. 

  • Select the traffic_parameters.json file in Resources/Data/Configurations. 

  • Optional: Click Test to see that FME Flow successfully loads the parameter configurations from the JSON file. You can also Preview how the parameters look and behave as user parameters in the FME Flow interface. 

  • Scroll to the bottom of the page and click Save. 

4) Run the App

  • Click View App to reopen the app.
    • If you still have the app open from step 1, refresh the browser tab. 
    • When the app loads, the default date matches the date set in the JSON file, and the event type and region parameters display all the options through the Open511 API. 

  • Select today's date, some event types and regions, then Run the app. 
    • If the date you select is too old, the workspace will error. 

    • The app uses the data streaming service and outputs an HTML report with an interactive map to select road alert records and view more information.

Jennifer's app can now supply default values and parameter choices from a JSON file, and they update as the file changes.
