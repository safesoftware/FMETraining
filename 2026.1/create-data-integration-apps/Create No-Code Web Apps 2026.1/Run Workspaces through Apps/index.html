Creating Workspace Apps

FME Flow workspace apps provide a simple way to share FME workspaces with other users, allowing them to access FME functionality without prior FME experience. To create a workspace app, fill out a form to select the workspace, its transformation service, parameters for user input, and any customization options. 

Once you create a workspace app, FME Flow generates a URL that opens a web-based form, called an app. You can click the link to open it in your browser, copy it to share, or embed it in another website. 

The simple app interface does not require users to have any FME knowledge or even understand what an FME workspace is. You fill out the parameter values, if any, and click Run to run the workspace. 

Some example parameters include input source files, text or numeric values, choices to filter data, output file information, and more. We will cover more on parameters later in this learning path. To learn more about parameters in FME Flow, see the Build Self-Serve Workflows with Parameters course.

Once you click Run, FME Flow submits the workspace to an FME Engine to process, just like running a workspace manually on FME Flow. Once the translation completes, FME Flow returns the translation result to you in the app.   

You may only run one workspace with a workspace app. To run multiple workspaces either in sequence or in parallel, you should use an automation app. We will cover automation apps later in this learning path. However, to learn more about automation apps, see the Trigger Automations through Apps lesson in the Job Orchestration in Automations course.

Parameters

If the workspace behind your app has user parameters, they appear in the Parameter Defaults section of the app form. Here, you set default values for the app user and decide which values they can change.

For each parameter, you set the value the app opens with. The Show in App toggle controls whether the app user sees the parameter and can enter their own value. If you disable it, the parameter doesn't appear on the app page, and the workspace runs with the default value you set. 

Reset Values returns every parameter to the default the workspace itself defines. Republishing the workspace with new default values does not change the values your app uses. The app keeps what you set here until you click Reset Values, which is worth remembering when you update a workspace, and the app does not display new default values.

The Dynamic Parameter Configuration section lets you use a JSON configuration to set default values and available choices each time the app opens, so a single app can behave differently for different users. 

We will cover Dynamic Parameters in more detail in the next course, Give End-Users Control with App Parameters.

Resource and Connection Permissions

If the workspace behind your app reads or writes Resources beyond the ones already named under Parameter Defaults, you grant access to those Resources in the Resource Permissions section of the app form. 

Access is granted to an entire Resources folder, not to individual files. For maximum security, create your own Resource Connection and place only the files you want to share in that folder, then grant access to it.

Workspaces often reach a database or a web service through a stored Connection. If your app's workspace needs a Database Connection or a Web Connection, you grant it in the Connection Permissions section. Granting a connection to an app lets the app run the workspace against that connection. It does not give app users the connection's credentials, and it does not let them use the connection anywhere else on FME Flow.

For more information on these permissions, check out this TGIF: Thank Goodness It's FME video on Managing Flow App Permissions in 2026.1. 

Accessing Flow Apps

Once you create a Flow app and FME Flow generates a URL to access it, use that URL to access the app. You can copy and paste the URL into another browser, send it to a colleague, or embed it on another website. Keep your intended audience in mind to ensure they can access the app. FME Flow apps have two levels of accessibility permissions: individual app permissions and FME Flow network access. 

When you create your workspace app, you must specify who can access your app through the App Security setting. Public gives full access to anyone with the URL. Private restricts access to the roles and users you list under Allowed Roles and Allowed Users; those users must log in to FME Flow before access is granted, and everyone else is denied. 

User Can Upload specifies whether app users can upload temporary files to use as inputs to the workspace. This setting is necessary in self-serve workflows where the app user brings their own dataset to input to the app, and comes with the security risk of those files being temporarily stored on FME Flow. 

See our documentation on User Management for more information on users, roles, and permissions on FME Flow. 

The next level of Flow app accessibility depends on whether your FME Flow administrator set up your FME Flow on an internal or external network. While you do not need to know the administration tasks to set up FME Flow, it is crucial to know whether your FME Flow is publicly accessible for app access. If your organization restricts FME Flow to an internal network, you will not be able to access FME Flow or Flow apps outside of that network. If this is the case and you share your app with users outside your organization, or embed it in a publicly facing website, external users will not be able to access and use your app. If your FME Flow is publicly accessible and you set your app's App Security to Public, anyone with access to the app link will be able to access and run your app. 

Administration tasks like making FME Flow publicly accessible are outside the scope of this course. For more information, see Enabling FME Flow for Public Access. 

Exercise

Jennifer, a GIS specialist, is creating a self-serve data portal. She wants her colleagues to upload their CAD data and validate it against rules. She will use a workspace app to share the workflow with her colleagues, allowing them to run the FME workspace without requiring any prior FME experience or knowledge. 

Jennifer's workspace reads CAD water line data, runs validation checks on the features, and generates an HTML report that varies depending on whether the features pass validation or fail the tests.

In this exercise, you will:

  • Create a workspace app that runs a workspace with the Job Submitter service.
  • Run the app and inspect the validation report it produces.

1) Log In to FME Flow

  • Navigate to FME Flow and log in. 

2) Create the Workspace App

Jennifer has already published the workspace to FME Flow for the app.

  • From the Dashboard, click the Create Workspace App shortcut. 
    • This opens the Create Workspace App form for you to fill out. 
    • Instead of using the Dashboard shortcut, you can open Flow apps on the side menu, ensure you're on the Workspace Apps tab, and then select Create to open the same form. 

  • Name your workspace app CAD-Data-Validation and optionally give it a similar Title.

  • In the Description field, enter the following text.
Run this workspace to ensure that the watermain data is line data, with a pipe diameter larger than 0, and passes the OGC Valid test.
  • Configure the following parameters:
    • Repository: Data Validation
    • Workspace: CAD_Data_Validation.fmw
    • Service: Job Submitter

  • Under App Access, leave App Security set to Public. 
  • Toggle on User Can Upload.

  • Expand Parameter Defaults and leave both parameters set to Use Default, with Show in App selected.
    • The first parameter takes the AutoCAD files the app user uploads. The second sets where the HTML report of validation results is written.

  • Skip the remaining sections, scroll to the bottom of the form, and click Create.

3) Open and Run the App

FME Flow summarizes the app and shows the app URL.

  • Click View App to open it in another browser tab.
    • FME Flow loads the app and displays the parameters that feed into the workspace. 

  • Leave both parameters at their default values and click Run.
    • If you cannot reach C:\FMEData on the server hosting your FME Flow, change the Destination HTML File parameter to a location you can reach.
    • The app shows Running while an FME Engine processes the workspace, then Completed. It writes the output HTML file to the file location in the parameter.

4) Inspect the Output

  • Navigate to C:\FMEData\Output\ in File Explorer. 
  • Open the validation_results.html file.
    • The report maps the features that failed validation and lists why each one failed.

You have created a self-serve data portal where users can upload files and run a workspace to validate CAD data.
