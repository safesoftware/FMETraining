## AI Accuracy

- 69. **Optimize model to reduce API costs.** I chose `gpt-4o-mini` in initial testing, but we could do additional benchmarking to look for a cheaper model that meets our needs.

- 53. **Generic screenshot alt text makes it impossible for the LLM to identify affected screenshots.** When alt text says "Inspecting points and attributes" instead of naming the window or dialog, the LLM can't connect a UI rename to that screenshot. Short-term fix in `ASSESSMENT.md`: *"Use alt text as the primary description of the image. Only flag a screenshot if its alt text or immediately surrounding text explicitly names the UI element changed by the Jira issue — do not infer from the general section topic."* Long-term: add an optional pipeline step that passes actual images to a multimodal LLM call to generate descriptive alt text for screenshots with generic alt text.

- 52. **Interactive `/update-scope` skill.** The scope escalation framework (inline edit → new section → new lesson → human review) is now documented in `prompts/EDITORIAL_GUIDELINES.md` and injected into the edit suggestions prompt. Remaining: build a Claude Code skill (`/update-scope`) that walks through these criteria interactively for a given Jira issue and lesson, as a complement to the automated prompt-based approach.

- 72. **FMEENGINE-based suggestions have a 0% acceptance rate and should be filtered for conceptual lessons.** Retrospective analysis of run `20260317T155430-28a8` (19 lessons, 2024.2→2026.1) shows: FMEENGINE suggestions = 0 accepted / 35 rejected / 6 reworded (0% accept rate); FMEFORM suggestions = 16 accepted / 21 rejected / 4 reworded (39% accept rate). Engine-level changes (transformer behavior, format behavior) never make it into training content because lesson text describes procedures at a high level rather than documenting internal transformer mechanics. Fix: In `prompts/EDIT_SUGGESTIONS.md`, add a rule: *"For issues in the FMEENGINE project, only suggest a change if the lesson explicitly demonstrates that specific behavior with numbered step-by-step instructions naming the exact transformer — do not suggest changes to conceptual overview paragraphs, learning objectives, or transformer description tables."* Optionally, add a post-processing filter in `edit_suggestions.py` to suppress FMEENGINE-keyed changes in lessons classified as fully conceptual by `_build_section_classification()`.

- 73. **Screenshot coverage gap: tool misses ~41% of screenshots that actually changed.** Retrospective of run `20260317T155430-28a8` found 31 missed screenshot updates vs. 44 suggested. The tool flags screenshots only when a Jira issue implies a UI change in that area, but screenshots are retaken whenever the FME interface updates visually — independent of Jira coverage. Fix: Add a post-processing pass in `edit_suggestions.py` (after LLM response) that compares the lesson's image filenames against a `known-screenshots-{version}.json` index of unchanged images for the target version. Any non-decorative image not in that index, and not already in `screenshot_updates`, should be auto-flagged. As a simpler short-term alternative: flag all non-decorative images in lessons where at least one Jira issue implies UI changes, since those lessons are almost always fully retaken. Note: This addresses *coverage* (missed images), which is distinct from issue #53 (accuracy of the images that are flagged).

- 74. **Suggestions with `original_text` not found in source HTML should be removed.** Retrospective found 3 "NA" suggestions in run `20260317T155430-28a8` (all in "Understand Coordinate Systems") where the LLM generated `original_text` values that don't appear in the actual lesson HTML. These appear in the report as unapplyable suggestions and waste reviewer time. Fix: In `edit_suggestions.py/_call_openai()`, after receiving the LLM response and applying existing post-processing filters, add a validation pass: normalize each `original_text` (strip HTML entities, collapse whitespace) and check it is a substring of the normalized lesson HTML. Remove any `changes` entry that fails this check, and log it to the run debug output. This pairs with the existing `_ensure_version_changes()` pattern of scanning the HTML directly.

- 75. **`_ensure_version_changes()` generates empty-heading suggestions, breaking section-level context.** The function at `pipeline/edit_suggestions.py:821` always sets `"heading": ""` for auto-generated version-string replacements. In the report UI, these suggestions appear without section context (the heading chip is blank). In the retrospective tool, they're not matched to the section that changed, causing false "missed" detections for sections that actually were covered by a version change. Fix: After locating the match position, scan backward in `lesson_html` from `m.start()` to find the nearest preceding `<h2>` or `<h3>` tag and extract its text content as the `heading` value. This requires a small regex or BeautifulSoup parse of the preceding HTML slice.
